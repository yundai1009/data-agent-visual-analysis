## 1. 目标

对**已生成完成的报表**做**图表层面的局部精细化修改**，输出新的完整图表 spec + 变更对比清单。

**强制约束（用户定义）**

1. 只做图表层编辑，**不重新执行 Agent ReAct 推理、不调用外部工具取新数据**，复用报表关联数据集与计算结果。
2. 字段修改必须复用**数据画像**校验规则：标识符/编码 ID 类字段严禁作 Y 轴/数值度量，只能作分类 X 轴；指定非法 Y 轴则拒绝并说明原因。
3. 指令模糊时向用户确认（目标图表 + 修改参数）。
4. 输出完整新 spec + 变更对比清单（旧 → 新）。

## 2. 已确认的设计决策

| 决策 | 结论 |
|---|---|
| 数据来源 | **A**：编辑时读报表关联数据集的 parquet，用**已有画像** + 本地 pandas 重聚合（不调 LLM/Agent）。原因：报表存的 `图表配置.数据` 只含旧字段聚合结果，换轴/切占比/加筛选在旧聚合数据里无对应列，必须回到数据集重算。 |
| 持久化 | **另存为新报表**，原报表不动；新报表 `parent_report_id` 指向原报表（可另加列或复用数据集版本链思路）。 |
| 交互入口 | **自然语言指令 + 结构化编辑面板**双入口，NL 与面板归一化为同一结构化编辑模型。 |
| 筛选语义 | 筛选作用在**原始 df（重算前行过滤）**，再按新参数重聚合。 |
| 占比切换 | "样本计数占比 / 数值加权占比" 实现为同一指标两种聚合：计数（分母=行数）vs 求和（分母=数值和），复用 `_聚合数据`。 |
| 编辑指令表示 | **1A 结构化编辑模型**：白名单枚举动作，NL/面板归一化后可审计可测。 |

## 3. 架构

```
POST /reports/{report_id}/refine      ← 单端点，编辑动作 + 模糊确认两用
  body: { 指令?: str, 参数?: 编辑模型, 确认ID?: str }
        │
        ▼
后端 api/routes/reports.py → _调编辑服务
  后端_核心/refine_report.py（新）
  1 读原报表 report_json（拿 dataset_id + 原 chart_config）
  2 读取数据集(存储层) → df + 数据画像        [复用，不重生成画像]
  3 NL 指令 → 结构化编辑动作（白名单 + 画像字段名匹配）  |  面板参数直传
  4 模糊检测 → 需确认则返回 confirm 载荷（约束 3）
  5 字段合法性校验（_合法字段 + 标识符/编码禁作 Y 轴）
  6 本地重聚合 → 新 chart_config（保持既有 spec 契约）
  7 组装 新报表 spec + 变更对比清单 → 保存新报表
        │
        ▼
返回 { 新报表ID, 新spec, 变更清单[], 需确认?, 拒绝原因? }
        │
        ▼
前端 EChartsChart 渲染新 spec + 变更对比面板
```

## 4. 后端模块设计

### 4.1 编辑动作模型（结构化、白名单）

```python
_允许动作 = {
  "改标题", "改子标题", "改图例名称", "改备注",
  "换X轴", "换Y轴", "改X轴别名", "改Y轴别名", "改坐标轴范围",
  "切图表类型",              # 柱↔折↔饼↔散点
  "改系列颜色", "切换数据标签", "改图例位置",
  "切占比逻辑",              # 样本计数 / 数值加权
  "加筛选",
}
```

每个动作 → 一个校验+应用函数，操作对象是 **编辑参数**（x轴/y轴/图表类型/颜色/筛选…）→ 产出新 chart_config。

**NL → 结构化动作 解析**（`refine_report.py` 内新增 `_解析编辑指令(文本, 画像)`）：
- 轻量关键词正则动作识别：`X轴/横轴/x 轴 →`、`Y轴/纵轴/y 轴 →`、`标题改为/叫`、`换成/切换成/改成 + 图表类型词`、`占比/按计数/按数值`、`只看/筛选/过滤 + 值`、`颜色/图例/标签/别名/范围` 等。
- 字段名用 `field_selector._匹配意图字段`（画像字段名匹配，命中才采纳——对齐 M25 白名单风格，防幻觉字段）。
- 识别不到动作或字段名不唯一 → 返回 `需确认`（约束 3）。
- 不引入新 NLU 依赖；动作白名单与 `_允许动作` 一一对应。

### 4.2 标识符/编码字段识别（约束 2）

画像现有 `字段类型/数值字段/分类字段/日期字段/文本字段`。新增识别器 `标识符字段(画像)`：
- 字段名命中 `id/编号/编码/code/序号/UUID/单号` 等模式，或
- 唯一值数 ≈ 行数（高基数）且为数值/文本类型

标记为 `标识符字段列表`，**禁止出现在 Y轴/数值度量**，仅可作 X 轴/分类维度。

### 4.3 复用既有能力

| 能力 | 复用 |
|---|---|
| 读数据 + 画像 | `存储.读取数据集(user_id, dataset_id)` → `数据`/`数据画像` |
| 聚合 | `report_generator._聚合数据(df, x, y, group, agg)` |
| 字段合法性 | `field_selector._合法字段` + 新增标识符校验 |
| chart_config 契约 | 沿用现有键（类型/标题/X轴/Y轴/颜色/数据/筛选/TopN/对比），前端 `EChartsChart` 无需改渲染 |
| 保存报表 | `report_repo.保存报表(...)` |
| 编辑溯源 | 新报表记录 `来源报表ID`（parent） |

## 5. 前端设计

- 报表详情加「编辑图表」入口 → 抽屉/弹窗，内含：
  - 自然语言输入框（编辑指令）
  - 结构化面板（字段下拉/颜色/图例位置/占比逻辑/筛选）
- 提交 → 调 refine；响应含 `新spec` 则用 `EChartsChart` 直接渲染，`变更清单` 显示「旧 → 新」对比。
- `需确认` 时弹确认框（目标图表 + 待确认参数），确认后带 `确认ID` 重提。

## 6. 测试计划（TDD）

- 编辑动作：每类动作单测（改标题/换轴/切类型/切占比/加筛选/改色…）
- 约束 2：标识符/编码字段作 Y 轴被拒 + 原因说明；作 X 轴允许
- 约束 3：模糊指令返回需确认（不擅自改）
- 无 ReAct：编辑路径不触发 LLM/工具（mock 断言）
- spec 契约：新 chart_config 键与旧一致，EChartsChart 可渲染（前端测试）
- 回归：现有全量测试不破

## 7. 风险与取舍

| 风险 | 对策 |
|---|---|
| 重聚合与原口径不一致 | 复用同一 `_聚合数据`，仅参数变；TopN/对比沿用原配置 |
| 大数据集重算慢 | 本地 pandas，可复用已有 parquet；必要时限行数或仅对现有维度重算 |
| 新报表膨胀 | 另存不改原，父链可溯源 |
| NL 解析歧义 | 结构化模型 + 需确认机制（约束 3）兜底 |

## 8. 不做（范围外）

- 不做多图联动、不做跨报表合并、不重新调用外部数据源、不做 Agent 自动标题优化。
