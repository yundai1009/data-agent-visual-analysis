# PC 端桌面应用（Electron 壳）设计文档

**日期**：2026-10-06
**状态**：待评审
**代码位置**：`D:\python\数据分析agent\电脑pc端\自助式数据分析Agent平台`（主仓库完整副本，同 remote / 同 HEAD `6a99a32`，作为 PC 端独立演进基底，不 push 主仓库 main）
**平台**：仅 Windows

---

## 1. 目标与范围

把现有「Web 服务 + 浏览器」形态（FastAPI 托管 React dist，`launch_gui.pyw` 起后端后 `webbrowser.open`）升级为**真正的独立窗口桌面应用**：

- 双击图标 → 独立窗口（无浏览器标签页/地址栏），像微信/QQ 那样
- **全功能保留**：上传/分析/图表/导出/分享/管理/精细化编辑全部可用
- 桌面能力：系统托盘常驻、文件拖拽上传、单实例、开机自启
- 分发形态：安装包（NSIS，带图标/卸载/快捷方式）+ 免安装 zip
- 更新能力：检查更新（先走"跳转下载"降级方案，签名证书到位后接 `electron-updater` 全自动）

**非目标（本期不做）**：跨平台（Mac/Linux）、云端账号与数据同步实现（架构预留，本期只保证本机数据可用且可迁移）、代码签名证书采购。

---

## 2. 技术选型与理由

| 方案 | 结论 | 理由 |
|---|---|---|
| **Electron + PyInstaller 后端子进程** | **选定** | 用户 5 项需求（拖拽/托盘/更新/安装包/全功能）全是 Electron 成熟生态；Chromium 渲染可控；前端 dist 零改动 |
| pywebview | 否决 | 纯 Python 单一栈更轻，但托盘/拖拽/自动更新/安装包都需自建，产品化周期显著拉长 |
| Tauri | 否决 | 壳体积最小，但项目无 Rust 栈；5 项需求生态要手写；Python 后端仍需 PyInstaller，收益低 |

**核心思路：零改动复用**。现有 FastAPI 后端 + React 前端 dist **一行不改**，Electron 只做「启动器 + 窗口 + 桌面能力」外壳。

---

## 3. 总体架构与进程模型

```
┌──────────────────────────────────────────────────┐
│ Electron 主进程（electron/main.js）                 │
│  单实例锁 · 空闲端口分配 · spawn 后端 · 生命周期     │
│  托盘 · 拖拽拦截 · 窗口管理 · 更新检查               │
└───────────────┬──────────────────────────────────┘
                │ 仅本机回环 127.0.0.1
┌───────────────▼──────────────────────────────────┐
│ Python 后端子进程（PyInstaller onedir 产物）         │
│  uvicorn api.main:app --host 127.0.0.1 --port P    │
│  env 注入：AUTH_ENABLED=false / PORT / DAA_SQLITE_PATH │
│  cwd = %APPDATA%\数据分析Agent（parquet 相对路径落此） │
└──────────────────────────────────────────────────┘
```

**为什么免认证（AUTH_ENABLED=false）是安全的**：现有后端启动自检（`api/main.py` `_启动安全自检`）规定"免认证模式只允许监听回环地址，绑定 0.0.0.0 直接拒绝启动"——单机桌面应用天然只服务本机，这条既有安全闸门物理堵死公网裸奔，天然匹配桌面分发。

## 4. 数据与配置（关键约束）

**用户数据一律落 `%APPDATA%\数据分析Agent\`，绝不落安装目录**（`C:\Program Files\` 不可写）：

| 内容 | 位置 | 注入方式 |
|---|---|---|
| SQLite 库 | `%APPDATA%\数据分析Agent\data\daa.db` | env `DAA_SQLITE_PATH`（`settings.EnvConfig.SQLITE_PATH` 支持覆盖） |
| 数据本体 parquet | `%APPDATA%\数据分析Agent\data\parquet\` | 后端 `_PARQUET_DIR = Path("data/parquet")` 是**相对 CWD** 的路径 → 只需把子进程 `cwd` 设为 `%APPDATA%\数据分析Agent\data`，**后端零改动** |
| 上传/导出/备份/chroma | 同上相对路径 | 同上（cwd） |
| 日志 | `%APPDATA%\数据分析Agent\logs\` | Electron 侧收集后端 stdout/stderr 写文件 |
| LLM 配置 | 沿用应用内「AI 模型」页 BYOK 落库 | 无需注入 env |

**配置注入机制**：`config/settings.py` 用 `load_dotenv(override=False)`——系统环境变量优先级高于 `.env`。Electron `spawn` 时传入完整 `env` 对象即可**无 .env 文件**驱动后端（打包环境无项目根 `.env` 亦可启动）。首次运行由 Electron 自动创建目录结构。

**换机迁移 = 拷 `%APPDATA%\数据分析Agent\` 整个目录**（写进用户文档）。

## 5. 启动流程

```
双击安装后的 exe
 1. 单实例锁 requestSingleInstanceLock()
      └─ 已有实例 → 聚焦其窗口并退出（防双重启动抢端口）
 2. 探测空闲端口 8000→8001→…（对齐现有 启动.ps1 的 Get-FreePort 逻辑）
 3. 确保 %APPDATA%\数据分析Agent\data 存在
 4. spawn 后端 exe：{ env: {AUTH_ENABLED:'false', HOST:'127.0.0.1', PORT, API_PORT,
                          DAA_SQLITE_PATH}, cwd: <APPDATA>\data, windowsHide: true }
 5. 健康轮询 http://127.0.0.1:PORT/healthz（超时 ~30s → 弹错误对话框 + 写日志 + 退出）
 6. 创建 BrowserWindow（无地址栏、1440×900、minWidth 1024）加载 http://127.0.0.1:PORT
 7. 注册托盘图标
```

**退出语义**：关窗口 = 隐藏到托盘（后端继续运行，报表/图表即时可用）；托盘菜单「退出」= 杀后端子进程 + `app.quit()`（含 `before-quit` 里 kill 子进程，避免孤儿进程占端口）。

## 6. 桌面能力实现

| 能力 | 实现要点 |
|---|---|
| 托盘常驻 | `Tray` + 模板图标（避免任务栏黑边）；菜单：显示主窗口 / 退出；双击托盘图标唤回窗口 |
| 单实例 | `app.requestSingleInstanceLock()` + `second-instance` 事件聚焦窗口 |
| 文件拖拽上传 | 渲染进程 HTML5 drop 拿到 `File` 对象，经 preload 暴露的 `window.desktopAPI.取文件真实路径(file)`（主进程 `webUtils.getPathForFile`）取绝对路径（仅用于回显/日志）→ **复用现有 multipart 上传接口直传**（File 对象本身就是可上传体，后端零改动）。拿不到真实路径时降级为纯 File 直传，功能不阻塞 |
| 开机自启 | `app.setLoginItemSettings({ openAtLogin })`，设置项持久化到 `app.getPath('userData')/settings.json` |
| 外部链接 | `setWindowOpenHandler` 把 http(s) 外链交系统浏览器打开，应用窗口不导航走 |
| 窗口状态记忆 | userData/settings.json 记录窗口最大化/位置，下次启动恢复 |

## 7. 打包与分发

**两段式打包**（各自独立，因分属 Python / Node 生态）：

```
① PyInstaller（打后端，onedir）
   electron/build-backend/daa-backend.spec
   入口脚本 electron/build-backend/backend_entry.py
     → uvicorn.run("api.main:app", host/port 从 env 读)
   hiddenimports: uvicorn/pydantic/chromadb/pandas/pyarrow 等动态导入依赖
   产物：dist-backend/daa-backend.exe（+ _internal/ 目录）
   验证：直接双击 exe + curl /healthz

② electron-builder（打桌面应用）
   electron/package.json 的 build 段：
     files: [electron/**, ../frontend/dist/**, dist-backend/**]
     win.target: nsis（安装包）+ portable/zip（免安装）
     nsis: 一键安装、桌面快捷方式、卸载、perMachine=false（免管理员）
     icon: 复用项目 logo.ico
   发布坐标：GitHub Releases（对外分发通道）
```

**敏感/冗余文件排除**：electron-builder `files` 白名单只含 `frontend/dist` 与 `dist-backend`，**`.env`、`data/`（含用户 daa.db/chroma/uploads）绝不进包**（data 在 .gitignore 亦不进版本库）。

## 8. 自动更新策略（分两阶段）

| 阶段 | 方案 | 前置条件 |
|---|---|---|
| 一期（本期） | 应用内「检查更新」按钮 → 请求 GitHub Releases API 比对版本 → 有新版则弹窗 + `shell.openExternal` 打开下载页 | 无需签名 |
| 二期（后续） | `electron-updater` 静默/自动下载安装 | 需 Windows 代码签名证书（SmartScreen 信任，个人证书约 ¥300–800/年）+ NSIS publish 配置 |

一期先把"能发现新版本并一键跳转"做实，二期拿到证书后平滑替换为全自动。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| PyInstaller 漏收动态导入依赖（chromadb/pyarrow/uvicorn workers）导致 exe 启动即崩 | 显式 hiddenimports + 冒烟测试直接跑 exe（不只测打包成功） |
| 端口被占（用户本机已有 dev 后端） | 空闲端口探测，跳号不报错 |
| Electron/Chromium 体积（~200MB 含 Python 后端） | 接受；asar 压缩 + 后端 onedir 共享依赖 |
| 未签名安装包 SmartScreen 警告 | 一期文档说明"更多信息→仍要运行"；二期上证书 |
| data 目录被误打包（用户隐私泄露） | files 白名单 + 打包后人工核验安装包内容清单 |
| 两个副本同 remote 并发 push 冲突 | PC 端副本独立分支/不推 main（本期只在本地演进，打包验证后再决定仓库策略） |
