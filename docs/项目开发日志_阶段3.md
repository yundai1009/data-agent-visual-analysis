## 一、可选方向与决策记录

### 前端框架选择

| 方向 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **React 19 + Vite** | 生态最强，Tailwind 原生支持，组件库丰富 | 需额外学习 JSX | ✅ **选中** |
| Vue 3 + Vite | 上手简单，中文文档好 | 生态比 React 小，图表库选择少 | ❌ 团队 React 经验更多 |
| 保留 Jinja2 + HTMX | 零迁移成本 | 交互能力弱，无法实现复杂 UI | ❌ 无法满足设计需求 |
| Svelte | 打包小，性能好 | 生态最小，第三方组件少 | ❌ 风险高 |

### 样式方案选择

| 方向 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **Tailwind CSS v4** | 原子化 CSS，开发快，一致性高，Vite 插件原生支持 | 类名长，需适应 | ✅ **选中** |
| 手写 CSS Modules | 无额外依赖 | 样式膨胀快，命名混乱 | ❌ 维护成本高 |
| Ant Design | 组件丰富，开箱即用 | 样式重量级，定制困难 | ❌ 太重 |
| styled-components | 动态样式灵活 | 运行时性能开销 | ❌ 不必要的抽象 |

### 布局方向

| 方向 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **左侧可折叠导航 + 单页内容** | 空间利用率高，现代 SaaS 标配 | 页面间跳转需路由 | ✅ **选中** |
| 三栏等宽布局 | 一屏可见全部 | 信息密度太高，用户反馈"臃肿" | ❌ 用户评价不佳 |
| 聊天式单栏布局 | 极简，类似 ChatGPT | 功能入口深，操作步骤多 | ❌ 不适合数据分析工具 |

### 数据质量评级方向

| 方向 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A/B/C 三档** | 用户对等级制敏感，一目了然 | 需要定义清晰规则 | ✅ **选中** |
| 百分比显示 | 精确 | 用户需要自己判断好坏 | ❌ 不够直观 |
| 双档（良好/需关注） | 简单 | 粒度太粗，无法区分中等质量 | ❌ 原方案，不够用 |

### 数据清洗 API 设计

| 方向 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **浅拷贝 + 只读清洗** | 不修改原始数据，误操作可恢复 | 内存消耗稍高 | ✅ **选中** |
| 原地修改（mutate） | 性能好 | 误操作无法恢复，风险高 | ❌ 安全优先 |
| SQL 级清洗 | 适合超大表 | pandas 已覆盖全部场景，增加复杂度 | ❌ 没必要 |

## 二、踩坑记录

### 1. 数据画像 A/B/C 评级部分已存在

打开 `数据画像.py` 准备写 A/B/C 逻辑时，发现代码中**已经包含了 A/B/C 三档分级逻辑**，只是缺少 `等级说明` 字段。这说明可能有之前的自动化工具或会话已经修改过这个文件。直接补全字段即可，不需要重写。

### 2. api/routes/__init__.py 为空文件

FastAPI 的 `include_router()` 依赖模块直接 import，不需要在 `__init__.py` 中显式导出。但一开始不确定是否要加导出语句，翻看已有路由发现它确实是空文件，踩了个小心理坑。

### 3. CleanDatasetResponse 已有但字段不同

`contracts.py` 中已经定义了 `CleanDatasetResponse`（原字段：数据集ID、原行数、清洗后行数、去重行数、填充缺失值、删除空行、数据画像），但我写的 clean API 返回了更细粒度的字段（包含清洗前列数、后列数、操作摘要 dict）。需要两边对齐，最终改 contract 适配真实 API 输出，保留原有类名但调整字段结构。

### 4. LF/CRLF 行尾警告

Windows + Git 环境下每次 `git add` 都会报大量 LF→CRLF 警告。这是 Windows 的预期行为，不影响功能，但会误以为出错。解决方案：在 `.gitattributes` 中设置 `* text=auto`。

### 5. Vite 代理配置

前端开发时需要将 `/datasets`、`/reports`、`/health` 代理到后端 `localhost:8000`。一开始只配了 `/api` 前缀，但实际后端路由不带 `/api` 前缀，导致 404。修正：逐条配置路径前缀。

## 三、非预期行为

### 1. Quality 等级字段名不一致

效果图文档中使用 `评级: "A"`，但后端代码实际输出时同时包含 `等级: "优秀"`（中文标签）和 `评级: "A"`（字母等级）。前端需要根据 `评级` 字段取值，而非 `等级`。

### 2. 字段类型推断不完全基于 dtypes

pandas `dtype` 无法区分"分类"和"文本"字段。后端的 `_字段分组()` 函数使用"唯一值数量 ≤ 行数 50%"的启发式规则判断。这可能导致短文本字段（如只有几个值的描述）被错误归为"分类"。目标准确率约 85%，极端情况需用户手动修正。

### 3. 缺失率计算口径

`总缺失值 / (行数 × 字段数)` 的缺失率计算方式较为严格：如果一个数据集有 20 个字段但只缺了 1 个值，缺失率 = 1/(100×20) = 0.05%，评级 A。但如果一个字段全空（20 个值缺失），缺失率 = 20/(100×20) = 1%，仍然是 A 级。这可能导致"单字段全空但整体评级仍为 A"的非预期行为。
