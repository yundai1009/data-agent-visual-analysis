## 一、为什么走 SQLite 而不是 MySQL

### 决策依据
- **部署目标是 A**：代码发 GitHub，面试官本地 clone 跑
- **面试官体验**：装 MySQL 是减分项（要装服务器、配账号、建库、配 `.env`，10 个面试官 9 个会在这步放弃）
- **SQLite 是 Python 标准库**：`sqlite3` 内置，`pip install -r requirements.txt` + `python api/main.py` 直接能跑
- **向后兼容**：SQLite 数据类型与 pandas / DataFrame 互转简单，不破坏现有契约
- **面试可讲**：能讲清"为什么选 SQLite 而不是 MySQL/Postgres" 是工程权衡，不是图省事

### 不选 MySQL 的原因（面试可讲）
1. 部署成本：MySQL 需要"装服务器 + 配账号 + 建库" 三步，SQLite 是 0 步
2. 维护成本：MySQL 服务进程要管启停、端口、日志；SQLite 是文件，跟项目代码同生命周期
3. 性能错觉：在"单用户单进程"的求职作品集场景，SQLite 与 MySQL 的性能差异**完全无感**
4. MySQL 真正的强项是"多用户高并发"+ "权限隔离"，这两个本项目阶段 1-2 都不需要
5. 升级路径：SQLite → MySQL 的迁移成本远低于反过来，**先 SQLite 后 MySQL 是演进方向**

## 三、安全姿态（在写代码前先钉死）

| 项 | 规则 |
|---|---|
| SQL 注入 | 一律参数化查询 `?`，**禁止字符串拼接 SQL** |
| 文件路径 | SQLite 文件路径只从 `EnvConfig` 或默认值读取，不接受用户输入 |
| 数据隔离 | 表名固定 `datasets` / `reports`，不接受用户输入作表名 |
| DataFrame 持久化 | 把 DataFrame 序列化为 JSON 字符串存进 SQLite TEXT 列，读出时 `pd.read_json` 反序列化 |
| 图像/画像 | 同样 JSON 序列化进 TEXT 列 |
| 事务 | 写操作用 `with conn:` 上下文管理自动 commit/rollback |
| 连接 | 每次请求用完即关，不留长连接 |
| Schema 演进 | 第一版 schema 用 `CREATE TABLE IF NOT EXISTS`，未来加字段走迁移脚本 |

## 七、决策记录

### 决策 1：SQLite 而不是 MySQL

| 维度 | SQLite | MySQL |
|---|---|---|
| Python 标准库 | ✅ `sqlite3` 内置 | ❌ 需 `pip install mysqlclient` 或 `pymysql` |
| 部署成本 | 0 步（文件即数据库） | 多步（装服务器 + 配账号 + 建库 + 配 `.env`） |
| 面试官 clone 后跑通 | `启动.ps1` 一键即可 | 需要本地装 MySQL 服务器才能跑通 |
| 多用户高并发 | 弱（写串行化） | 强 |
| 与 pandas 互转 | 简单（JSON 序列化） | 需 SQLAlchemy |
| 演进到 MySQL | 仓储模式接口不变，只换实现 | — |

本项目是"单用户单进程"求职作品集场景，SQLite 完胜。采访场景能讲："为什么选 SQLite 而不是 MySQL" 是工程权衡，不是图省事。

### 决策 2：仓储模式（Repository Pattern）

把存储细节从 API 路由层解耦：

```
api/routes/datasets.py  ──┐
                          ├──► 后端_核心.存储.数据集仓储
api/routes/reports.py   ──┘
```

未来 SQLite → MySQL/Postgres：只换 `sqlite_repo.py` 的实现，路由层不动。这就是仓储模式的价值。

### 决策 3：DataFrame 序列化用 JSON 而不是 pickle

- ✅ JSON：可读、可跨语言、安全
- ❌ pickle：反序列化有 RCE 风险（LLM 项目公开仓库最忌讳）
- 取舍：丢失 dtype，但读出后立即用 `生成报表数据` 重新算画像，不影响

### 决策 4：顺手补 `意图来源` 字段透传

阶段 1 在 `生成报表数据` 返回 dict 里塞了 `意图来源` 字段，但 `ReportGenerateResponse` 契约里没传出。本次顺手补上，作为阶段 2 的额外可观测性收益。前端接下来可以显示"LLM 推荐"或"规则兜底" badge。
