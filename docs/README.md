## 维护约定

1. **新文档**放进对应子目录；不确定的放 `工程文档/` 并在这里登记一行。
2. **开发日志**：每次实质性改动在 `开发日志/项目开发日志.md` 追加新阶段，并更新顶部导航表。
3. **本地保留、不推送**的文档在 `.gitignore` 中声明，不要 `git add`；
   已经写进本 README 的路径必须是 `git ls-files docs` 能查到的（空目录不登记）。
4. **plans / specs**：一份方案一份 `plans/<日期>-<名字>.md`，定稿后入库（沿用阶段 54 起的惯例）；
   配套技术选型放 `specs/<日期>-<名字>-design.md`。
5. **过期文档处理**：代码演进后本 README 与各工程文档要跟着核对，
   落后于代码的一律在表格里标 ⚠️，并在下一阶段计划里安排重写，不要留着误导。
