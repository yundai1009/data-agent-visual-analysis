# 产品定义 · 第一版（v1）

**产品名**：自助式数据分析 Agent 平台
**一句话定位**：面向 **0 基础、没有数据分析基础的普通人**——上传一份表格，说一句人话，直接拿到能看懂、能分享的图表和报表。
**主链路（三步）**：上传数据 → 说一句话 → 看报表。
**文档版本**：v1.0（第一版定义） ｜ **状态**：基于阶段一~九十（2026-07-22 → 2026-11-02）已交付代码的事实定义，不含未验证假设（假设一律单列，见 §6）。

> 口径约定：本定义中「已有实证」均来自仓库文档与测试基线，引用路径写清；「未知/需验证」一律不放结论里充数。
> 关键外部依赖事实（影响全部范围判断）：**单机部署（后端 FastAPI，DB 支持 MySQL/SQLite，向量记忆 Chroma 嵌入式、单进程单实例锁）**；**无公网隧道/域名/TLS 证书；无代码签名证书；未发布 GitHub Release；共享库高权限 DROP 受限**；SMTP 需自备邮箱；LLM 需自备 Key（参见 `docs/工程文档/生产级验收清单.md` §4、§5 与 `docs/开发日志/项目开发日志.md` 阶段九十 R20/R21/R22/R23）。

## 1. 目标用户

### 1.1 主用户（Primary）——"0 基础普通人"，第一版唯一必须服务好的人群

**画像一句话**：非数据分析岗位的普通业务人员 / 个体经营者，手上有表、心里没数，要的是"一个能看懂的答案"，不是"学会做图表"。

**典型角色（都是同一类人，不是五个细分市场）**：
连锁门店/餐饮/电商小老板或运营、销售/市场专员、人事/行政/财务、班主任/教务、中小团队负责人。

| 维度 | 具体描述（用于招募筛选） |
|---|---|
| **触发场景** | 手上有一张从系统导出的表（订单/会员/销售/考勤/成绩/库存），想知道"这个月怎么样 / 哪款卖得好 / 为什么比上月跌了"，要给老板或团队看，或要据此决定下一步动作 |
| **会不会用 Excel** | 会"双击打开 + 筛选 + 排序 + 简单求和"；**不会/不用**数据透视表、公式（VLOOKUP/SUMIF 勉强或不会）、不会 Python/SQL |
| **对图表的认知** | 分不清图表类型名（说不出"直方图 vs 柱状图"），但**能看懂带数字标签的柱状图/折线图**；不认识"桑基图/箱线图/瀑布图"这类专有名词 |
| **有多少数据** | 1~3 张表；每张几百~几万行（平台上限 50MB/单文件、单次全量 400 万行实测可入；**典型规模远低于上限**，见 §6 未知项） |
| **要达成什么** | "给我能直接看懂的答案 + 一张能发出去的图"；**全程不选字段、不认识图表类型名也能成功** |
| **失败会怎样** | 看不懂图 → 不信 → 流失；这是第一版主链路是否成立的分界线 |

**招募/访谈硬筛选条件**（可落地，不落空）：
1. 近 3 个月用过 Excel **打开过别人给的**表（不是自己建的分析表）；
2. 问"你会数据透视表吗"答 **不会 / 没听过**；没写过 SQL、没写过 Python；
3. 工作中确实存在"要分析一张表"的场景且 **最近 3 个月发生过**；
4. 能具体说出一件"上次想分析但没做成"的事（用于对焦）；
5. **排除**：数据/算法/研发岗位、统计/数学专业在读或从业。

### 1.2 次要用户（Secondary）——"进阶业务 / 轻度数据人员"，专业版人群

**画像**：运营/产品/项目经理/财务主管，会一点 Excel 透视、认识图表，有**重复性**分析需求。

| 维度 | 描述 |
|---|---|
| **触发场景** | 月度/周度复盘要重复做；多文件跨月对比；要沉淀模板、定时生成；要追溯"这张图从哪张表哪个字段来的"（血缘） |
| **能力前提** | 会用数据透视表或至少理解"分组统计"；有 ≥2 次同结构重复报表经验；愿意为"省重复劳动"学一点配置；可能自带 LLM Key 或要选模型 |
| **要达成什么** | 一次配好、重复复用；对比可重现；能解释结果来源 |

**招募筛选**：3 个月内做过 ≥2 次同结构重复报表；用过至少一种 BI/图表工具；能明确说出"每月都要做同样的表"。

### 1.3 第三类（管理/采购侧，非终端使用人）

- **平台运营者/管理员**：管理后台用户，看"注册→传数据→出报表→回访"漏斗、用户管理、审计日志——**内部角色，不是终端用户**；
- **桌面版购买/决策者**：金融、医疗、政企的 IT 或合规负责人，在意"数据不出本机/可私有化"——**不是日常使用者**，但其"数据不出域"诉求是竞品差异化的核心卖点（`docs/竞品对比-数据分析Agentvs豆包类大模型.md` 第 1 条卖点）。

### 1.4 明确"不是谁"（排除人群，第一版不做他们）

| 排除人群 | 为什么不是 |
|---|---|
| 数据科学家 / 分析师 / 算法 | 要 Python/SQL 自由编程、建模、A/B 检验；平台太浅，需求由"自由写代码"满足，不会来自动化 |
| 能熟练写 SQL/Python 的工程师 | 宁可写脚本，不信自然语言出图 |
| 需要实时流式/大屏/物联网数据 | 只吃**静态文件**，无数据库直连、无实时流 |
| 需要多人实时协作/企业级权限审批/合规留痕的组织 | v1 单实例单进程、无组织/角色审批模型；只有"分享链接+密码+协作者白名单"粒度的公开分享（`docs/工程文档/权限隔离审计报告.md` R2） |
| 需要 OCR/图片/PDF 表格/非结构化 | 只吃结构化 CSV/Excel |
| 只做汇报、手上无数据、也不想碰数据的高管 | 没有"上传"这一步的前提 |
| 已用专业 BI（FineBI/Tableau/Power BI）且有专职分析师的团队 | 功能数比不过，定位不同；对比结论见 `docs/竞品对比-数据分析Agentvs豆包类大模型.md` §四 |

## 2. 核心场景（5 个）

> 结构统一：谁 / 什么时候 / 手上有什么 / 说一句话 / 期望拿到什么 / 成功长什么样。每个场景末尾标注「现有产品覆盖情况」。

### 场景 A（首用·单表看懂）——主链路，第一版最核心
- **谁**：小李，连锁便利店店主，0 数据基础。
- **什么时候**：月底，想看看这个月各店卖得怎么样，要拿给股东看。
- **手上有什么**：一张从收银系统导出的 `销售明细.csv`（日期/门店/品类/金额，约 5000 行）。
- **说一句话**："按门店统计销售额"。
- **期望拿到什么**：一张**带数字标签**的柱状图 + 一段人话结论（"XX 店最高…"）+ 可导出的数据表。
- **成功长什么样**：打开→看到图→**10 秒内看懂"哪家店高"**→点导出→发到群里；全程不用选字段、不用认识"柱状图"。
- **覆盖**：✅ 主链路（上传→说一句→看报表），已有实证 P3/P5/P6（`docs/工程文档/真实用户全流程实测报告.md`）。

### 场景 B（跨文件对比）——对比分析，第一版第二高频
- **谁**：小王，电商运营，会一点 Excel。
- **什么时候**：每月 1 号，要对比 1–6 月各品类销量，看趋势与结构变化。
- **手上有什么**：6 份月度 CSV（月份/品类/销量）。
- **说一句话**：数据管理页勾选 6 份 → "这几份一起对比" → 配 来源轴=月份 / 主体轴=品类 / 指标=销量。
- **期望拿到什么**：多系列折线/柱状图 + 带"来源"列的数据表 + 可导出。
- **成功长什么样**：一次配好 3 个轴 → 6 个月同框 → 导出 → 放进月报；**重跑不重配**。
- **覆盖**：✅ 对比分析（P15，13 断言，含"标签排了序数据必须跟着排"回归；`docs/工程文档/真实用户全流程实测报告.md` P15）。

### 场景 C（专业版·重复复盘沉淀）——模板/定时/历史，专业版
- **谁**：小王（进阶），已用过，进入专业版。
- **什么时候**：每周一重复做同结构周报；老板要看固定模板。
- **手上有什么**：同结构每周数据 + 已做过一次的分析。
- **说一句话**："把上周的做法存成模板" / 设每周一 9:00 定时跑。
- **期望拿到什么**：一键复用模板生成同结构报表；定时任务自动产出；报表历史可回看、可复用。
- **成功长什么样**：第一次配好 → 之后每周打开即得，不再重新说一遍。
- **覆盖**：✅ 专业版能力（模板/定时任务/历史），能力表 `pro:true`（`frontend/src/utils/capabilities.js`）；入口已补（`docs/上线前功能审计-阶段八十四.md` §二）。

### 场景 D（看板+血缘）——沉淀与追溯，专业版血缘
- **谁**：张姐，销售团队主管，要把几张报表拼成一张"作战图"给团队看。
- **什么时候**：每周例会前；想搞清楚某张图从哪来的。
- **手上有什么**：3–4 张已生成报表（销售/区域/渠道/趋势）。
- **说一句话**：新建看板 → 勾选报表 → 拖到自由画布 → 加全局筛选器。
- **期望拿到什么**：一屏看全的看板（可导出 ZIP/图片）；点血缘图看到 **数据集→报表→复用字段** 三层。
- **成功长什么样**：拖完即存、刷新不丢；一个筛选器控制多图；血缘图能追溯"这张图用了哪张表的哪个字段"。
- **覆盖**：✅ 看板（网格/自由画布/全局筛选/导出 ZIP/图片，`docs/开发日志/项目开发日志.md` 阶段八十五、九十）+ 血缘图（`pro:true`）。

### 场景 E（离线·敏感数据）——桌面版，第一版**实际交付形态**之一
- **谁**：某金融机构内控人员，数据绝对不能出本机。
- **什么时候**：拿到一份客户/交易明细，要快速分析但严禁上传云端。
- **手上有什么**：笔记本（断网）、一份 Excel、NSIS 安装包。
- **说一句话**：安装桌面版 → 导入示例或本地文件 → 离线分析。
- **期望拿到什么**：本地完成 上传→分析→报表，数据不出本机；关掉再开数据还在。
- **成功长什么样**：装完即用，全程无网络请求；第二实例被**单实例锁**拒启（`docs/开发日志/项目开发日志.md` 阶段九十 ②）；默认 SQLite、零配置开箱（阶段九十 ③）。
- **覆盖**：✅ 桌面版（阶段五十六~五十九、七十八、九十）。
- **已知边界（如实）**：断网时智能路径若无本地 LLM 会自动降级到**规则引擎**仍出图（规则快速通道实测 0.00s 出图，`docs/工程文档/真实用户全流程实测报告.md` §5）；离线"聪明程度"取决于本地模型或规则兜底。

## 3. 第一版范围

### 3.1 必须有什么（Must-have）——每条给出"不做会死"的理由

#### A. 全用户（基础版）主链路 + 信任基线

| # | 必须项 | 不做会死的理由 |
|---|---|---|
| 1 | **注册/登录 + 邮箱验证码 + 找回密码 + JWT + 数据隔离** | 无真实认证则 `AUTH_ENABLED=false` 全站退化为单用户 `demo`，**任何人可读写删全部数据**（`docs/工程文档/权限隔离审计报告.md` R1）；权限隔离审计的可靠结论只对"正式模式"成立，**上线必须 `AUTH_ENABLED=true`**（`docs/上线前功能审计-阶段八十四.md` §一）。主链路断在第一步 |
| 2 | **上传 CSV/Excel + 多数据集管理** | 主链路第一步；没有数据对象就没有分析，链路断 |
| 3 | **一句话→出图（自然语言 + 规则/LLM 双轨，18 种图表，字段自动选择）** | 这是差异化核心与 0 基础成立的唯一可能——用户不会选字段、不认识图表名；没有它用户只能回到 Excel |
| 4 | **报表查看（图表+结论+数据表+决策记录）+ 历史回看/删除/重跑** | 主链路第三步；"能看懂"与"能沉淀"都在这；刷新后从后端历史读、删除后消失是"结果可信"的底线 |
| 5 | **图表可读性（默认带数据标签、子标题按数据结构生成、标题≤60字截断）** | 0 基础用户**看不懂图=不可信=流失**；阶段七十四 A 项正是按用户反馈补的，这是信任建立的直接证据 |
| 6 | **对比分析（多数据集跨文件，来源轴/主体轴/指标）** | "这个月比上个月"是 0 基础用户最常问的问题；只有单表则回答不了跨文件比较，B 场景失败 |
| 7 | **看板（卡片拼装 + 自由画布 + 全局筛选器 + 导出 ZIP/图片）** | 成果"沉淀+给团队看"；没有看板，多张报表只能一张张发 |
| 8 | **分享/导出（分享链接+可选密码、导出 xlsx/csv/pdf/json、公式注入转义、RFC5987 中文文件名）** | 定位原文就是"能分享"；不能分享=没有传播与协作价值。分享链接是**唯一设计性免登录放行口**，必须带密码/过期/限频（`docs/工程文档/权限隔离审计报告.md` R2） |
| 9 | **账号设置（资料/密码/模式切换）+ 帮助与版本** | 找回密码是主链路信任闭环；模式切换是基础/专业版入口；帮助是 0 基础"第一步干什么"的站内答案（阶段九十 R14） |
| 10 | **基础版/专业版能力隔离（`capabilities.js` 唯一真相源）** | 用户实测反馈"整体复杂度偏高、偏离定位"（`frontend/src/utils/capabilities.js` 文件头）；不隔离=定位失效。默认基础版=新用户只看到三步 |
| 11 | **管理后台（用户管理/审计/平台指标/价值漏斗）** | "做完了"要能变成"好不好"——价值漏斗是唯一口径（阶段九十 R15）；没有它运营无法判断是否值得继续 |
| 12 | **安全基线（启动自检 7 道、限流、审计、安全响应头、单实例锁、启动故障不静默）** | 单实例锁防 Chroma 索引被写坏（不可恢复）；启动故障不静默防"全绿监控+白屏"；`--workers>1` 拒启是 SQLite 写锁的硬约束（`docs/工程文档/生产级验收清单.md` §5） |
| 13 | **桌面版离线（Electron NSIS，默认 SQLite，单实例锁，换界面免重打包）** | **无公网隧道/域名/TLS 时，网页版无法对外**——桌面离线版是 v1 真正能交到用户手里的形态；"数据不出域"是竞品对比第 1 卖点 |

#### B. 专业版范围（存在且门控，属 v1 能力，但不阻塞基础版主链路）

模型选择 / 智能体模式 / 模板 / 定时任务 / 高级清洗 / 血缘图 —— 全部在 `capabilities.js` 中 `pro:true`，后端引擎**真实存在**（非"只有理论"，`docs/上线前功能审计-阶段八十四.md` §二 结论：4 项是"有引擎没入口"，入口已补）。基础版用户不感知，主动开专业版（`?mode=pro` 或账号设置）后可见。

> 说明：专业版能力**不进入**基础版主链路的"不做会死"判断——基础版主链路（上传→说一句→看报表+对比+看板+分享）不依赖它们也能成立。

### 3.2 明确不做（Not-doing，第一版）

| 不做 | 原因（与技术约束自洽） |
|---|---|
| 企业级多租户/组织/角色审批/协作权限（RBAC） | 单实例单进程、无组织模型；现有只到"分享链接+密码+协作者白名单"粒度 |
| 数据库直连 / 实时流式 / 大屏实时刷新 | 只吃静态 CSV/Excel，无 DB 连接器 |
| 多 worker + MySQL + Redis 共享限流的**生产并发部署** | Chroma 单实例锁、限流与并发闸均为**进程内**（`docs/工程文档/生产级验收清单.md` §5），多 worker 上限=worker 数×配额，限流形同虚设；桌面单机场景不需要 |
| 公网对外发布 / HTTPS | 无隧道/域名/TLS，代码解不掉 |
| 代码签名 / GitHub Release 自动更新 | 无证书/无发布凭据，检查更新现指向占位仓库 |
| OCR / 图片表格 / PDF 表提取 / 多模态 | 只吃结构化 CSV/Excel；多模态是竞品差距非 v1 目标 |
| 移动端原生 App | 响应式 Web 已够桌面/窄屏；v1 不投入原生 |
| 预测 / ML 建模 / 会员运营模块 | 不在能力表；阶段三十三仅"预测数据采集埋点"，预测模型是否成型**未验证**（见 §6） |
| 企业 SSO / LDAP | 超出单实例定位 |

### 3.3 范围与约束自洽性核对

- **单实例** ✅：桌面版默认 SQLite、`--workers 1` 硬闸、单实例锁（阶段九十 ②③）；
- **离线** ✅：Electron 内置后端+示例数据，断网可跑，智能路径降级规则仍出图；
- **无公网** ✅：v1 交付形态=桌面离线版 + 局域网/自托管网页版；公开注册/公网链接**不属于 v1 交付**（归 §4 暂缓）。

## 5. 核心能力可观察验收标准（重点）

> 每条：**怎么造数据 → 看什么信号 → 通过线 → 谁在什么时候测**。禁用"用户体验良好/性能优秀/界面美观"类不可判定表述。阈值均基于已有实证基线，未达标的"真实用户成功率"类指标在 §6 单列为需验证。

### 5.1 上传成功率

- **造数据**：准备 20 个不同结构文件（含：中文列名、空值/脏数据、日期、`../`路径穿越文件名、200 列宽表、16MB 大文件、恰好 50MB 边界、声明 60MB 超限），逐一经真实 HTTP 上传。
- **看什么信号**：每个请求的 HTTP 状态码 + `POST /datasets/` 响应 + 数据库行数核对（入库行数=文件数据行数）+ 服务端是否报 500。
- **通过线**：≤50MB、合法结构文件 **20/20 返回 200 且入库行数精确匹配，0 次 500**；>50MB 返回 413/400（业务文案"文件超过 50MB 限制"）且**无残留**；`../` 文件名被收敛（落库名为 `passwd.csv` 而非路径）。基线参考：P11 E1a/E1b/E2/E3 已实测（`docs/工程文档/真实用户全流程实测报告.md` §3）。
- **谁测**：工程 → 每轮发版前跑 `python scripts/e2e_real_user.py`（95/95 基线）+ 上传专项 + `tests/backend/test_产品定义v1_验收标准.py::test_验收51_宽表200列_上传成功且列数保真`（宽表 200 列保真，阶段九十R? 新增）；PM → 每月人工用 5 个不同真实文件抽查。

### 5.2 一句话出图正确性

- **造数据**：构造一张已知语义的表（如 `地区-销售额`、`月份-销量`、`会员等级-数量`）+ **30 条代表性语句黄金样本**（覆盖 占比/趋势/对比/分布/相关/TopN/专有图/口语变体）。
- **看什么信号**：生成的报表里 图表类型 + X 轴字段 + Y 轴字段 + 报表标题 + 意图来源（`LLM` / `规则` / `规则-快速路由` / `规则-受控语句`）+ 是否 500。
- **通过线**：30 条中 **≥90%（≥27 条）** 命中"正确图表类型+正确字段"，**0 条 500**；黄金样本离线 VCR 回归全绿（缺 cassette 即失败，不假绿）；断言"会员等级占比"稳定命中"会员等级"而非"会员地区"（阶段八十四第 12 项）。基线：P5 断言意图来源=LLM（7 步）；关键词覆盖度约 85%（`docs/关键词覆盖度审计-阶段八十四.md`）。**阶段九十R? 新增自动化**：`tests/backend/test_产品定义v1_验收标准.py::test_验收52_黄金样本30条_命中率不低于90`（18 图表矩阵 + 12 条高频口语变体，规则路径 30/30 命中，实测 100%）。
- **谁测**：工程 → CI（VCR 回放 + 上述 §5.2 自动化黄金样本）+ 每轮 E2E P5；PM → 每月人工跑 30 条黄金样本并登记命中/未命中（未命中即新已知盲区）。
- **边界（如实）**：多列同义、极端口语、多表关联仍可能选错字段（审计报告 §二盲区 2/3）——所以通过线是 90% 不是 100%，未命中的 10% 要落进反馈样本迭代词表。**阶段九十R? 修复**：4 条高频口语缺陷——「按地区统计销售额」掉表格、「对比各渠道销售额」x 轴错选地区、「按地区统计订单数量」y 轴错选销售额、「地区之间的销售额差异」掉表格——均已修（`后端_核心/field_selector.py`：`_匹配数值字段` 增字段名直接命中优先、`统计/汇总/合计` 与 `比较/对比/差异` 分支按需求文本选维度/数值字段、`_受控语句配置` 对追问注入上下文免疫）。

### 5.3 报表可读性（含历史回看）

- **造数据**：生成 1 张柱状图报表 + 1 张表格类报表 + 1 张含 `<script>` 标题的报表 + 1 张 60 字以上长标题报表。
- **看什么信号**：报表页 标题（≤60 字、省略号）、图表**默认带数据标签**、子标题按数据结构生成、结论区 Top3 与图表数值一致（数值降序喂 LLM，阶段五十二）、`数据表` Tab 可切换、`canvas` 渲染、决策记录可展开；刷新后报表从后端历史读、删除后消失、重跑不重配。
- **通过线**：柱状/折线图报表 5 要素全有；**表格类报表**：主区域显示"表格类数据请在下方『数据表』Tab 中查看"**且**数据表 Tab 有数据（F3 遗留 UX 如实判定，不判"主区域直接渲染"）；`<script>` 标题按纯文本渲染（P6b）；长标题截断不溢出。
- **谁测**：工程 → P6（7 断言）+ P6b；PM → 人工目检 3 张（柱状/表格/长标题）。

### 5.4 对比分析

- **造数据**：3 份中文名 CSV（月度，乱序上传），字段结构一致。
- **看什么信号**：数据管理页勾选 →"对比这几份" / 侧栏入口两路都能进；配 来源轴/主体轴/指标；生成的对比报表为**多系列图** + 数据表带**"来源"列**；血缘图显示 **N 个来源节点**（非 1 个）；导出含全部来源；精细化编辑后**标签排了序、数据必须跟着排**（阶段七十二 P15 回归）。
- **通过线**：P15 全部 13 断言通过 + 两路入口都可达 + 血缘多源节点正确。
- **谁测**：工程 → `python scripts/e2e_real_user.py`（P15）；PM → 每季度人工用真实月报 3 份复核一次。

### 5.5 看板

- **造数据**：≥2 张已生成报表（含 1 张表格类）；新建看板勾选报表。
- **看什么信号**：网格视图可拼装；切**自由画布**→拖拽/缩放→松手落库→刷新回显；**全局筛选器**（维度+取值）命中卡片正常、未命中淡出置灰（客户端完成）；**导出 ZIP**（xlsx/csv）一次下载、空看板 400、跨用户 404；导出图片/PDF 超限**等比降采样**、坏图不卡死（R10）。
- **通过线**：看板 3 断言 + 画布 5 断言 + 导出 ZIP 断言（真 zip 容器、csv 首字节 UTF-8 BOM、`format=pdf`→422）+ 无限渲染循环不复发（R10 内存）。
- **谁测**：工程 → 前端单测 + `test_看板导出ZIP`；PM → 人工拖 3 张报表并导出。

### 5.6 分享 / 导出

- **造数据**：1 张含敏感业务数据的报表 → 生成分享链接（免密 1 个 + 带密码 1 个）。
- **看什么信号**：匿名新上下文（无 token）可看免密链接；带密码链接错密码→拒绝（`hmac.compare_digest` + 10 次/10 分钟 429）；导出 4 格式（xlsx/csv/pdf/json）真下文件；`Content-Disposition` 文件名 RFC5987 中文可解回；导出注入转义（xlsx sheet XML 无 `<f>` 公式标签、csv 逐单元格无未转义 `= + - @` 前缀，含前导空白/TAB 绕过）。
- **通过线**：P6b/P7/P9 断言 + 导出注入专项全绿；**分享密码限频已自动化**（`tests/backend/test_产品定义v1_验收标准.py::test_验收56_分享密码失败限频_第11次429且按share生效`，阶段九十R? 新增：10 次错密码 401 → 第 11 次 429、超限后正确密码仍 429、按 share_id 隔离）。
- **谁测**：工程 → E2E P6/P7/P9 + §5.6 限频测试；PM → 人工带密码分享链接 + 错密码/限频验证。

### 5.7 账号与找回密码

- **造数据**：注册新用户（验证码从后端 dry-run 日志正则抓取）；登录；找回密码流程；改密。
- **看什么信号**：注册自动登录落 `/data`；验证码**一次性**（重发/重复用 400"验证码已使用"）；错码 400"请先获取验证码"；JWT 下发且长度正确（P4：len=235）；未登录访问受保护页被守卫弹回 `/login`；登出后再访问被弹回；改密后旧 token 吊销（`token_version` 对账）；SMTP 未配时响应 `email_sent:false` + 文案如实告知、不进 60 秒冷却。
- **通过线**：P2/P4/P10 + E11/E12 断言全绿；**配真实 SMTP 后真发一封验证码**（阶段九十 R5 已实测返回 True）；未配时如实提示不假装成功。
- **谁测**：工程 → E2E；PM → 配真实邮箱做一次真发 + 一次找回密码全流程。

### 5.8 桌面版离线可用

- **造数据**：断网环境 + NSIS 安装包（`electron/` 产物）+ 一份本地 Excel。
- **看什么信号**：安装后双击打开→本地后端启动（默认 SQLite，`DAA_SQLITE_PATH` 指向 `%APPDATA%`）；内置前端到手（阶段七十八真机冒烟）；示例数据可导入（阶段五十九 404 根修）；断网完成 上传→分析→报表；换界面**免重打包**（阶段七十五覆盖层）；**第二实例启动即被拒**（单实例锁，阶段九十 R1 在线反驳：真实第二进程报"安全拒绝启动…已被另一个后端进程占用"）；关掉重开数据仍在（SQLite 持久化）。
- **通过线**：安装→断网→三步全链路 1/1 成功；第二实例被拒且报错中文可行动；重启数据不丢。
- **谁测**：工程 → NSIS 构建冒烟 + 单实例锁测试（`tests/backend/test_阶段90_单实例锁.py`，5 条）；PM → 每发版前断网走查一次。

### 5.9 价值漏斗口径

- **造数据**：构造注册→传数据→出报表→回访四类用户数据（含同用户报表落在不同日期，模拟"回访"）；空库用例。
- **看什么信号**：管理员 `GET /admin/funnel`；四步均为**累计去重用户数**，每步占注册比例 + 相邻步转化率；`口径说明` 字段存在且写明"回访=报表跨天代理、非登录埋点"；空库返回 0.0（不除零）；非管理员 401/403 语义正确。
- **通过线**：漏斗 3 断言全绿 + 口径说明与数据同源（前端不另写一份）+ 管理员专属。
- **谁测**：工程 → `tests/backend/test_阶段90_价值漏斗.py`（3 条）+ admin 路由；PM → 用真实库核对一次数值合理性。
