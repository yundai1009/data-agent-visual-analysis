## 1. 为什么要有这份实测

单元测试能证明「函数 A 调用函数 B 返回 C」，证明不了三件事：

1. **真实用户点得动吗**——路由守卫、引导遮罩、弹窗首击竞态、按钮文案重复，这些都不是单测能覆盖的；
2. **极限输入进来会怎样**——16MB 上传、200 列宽表、路径穿越文件名、十万字需求、JWT 篡改；
3. **配置是否真的生效**——这条最贵：本轮实测第一次抓到「`/healthz` 全绿但向量记忆从来没工作过」。

第 3 条单靠任何离线测试都验不出来：单元测试里 embedding 是 mock 的，配错了照样绿。

## 2. 环境与方法

| 项 | 取值 | 说明 |
|---|---|---|
| 数据库 | **真实 MySQL 8.0.23**（库 `daa`） | 不是 SQLite、不是内存库；跑完按用户级联删干净并核对残留 |
| 端口 | `127.0.0.1:8012` | 8000 留给使用者自己的实例 |
| 前端 | `frontend/dist` **正式产物** | 不是 vite dev server，避免 HMR 掩盖问题 |
| 认证 | `AUTH_ENABLED=true` | 走真实的验证码/JWT 链路，验证码从后端 dry-run 日志里正则抓 |
| 浏览器 | Playwright Python + Chromium（headless） | 真点击、真输入、真下载 |
| 账号 | 每轮随机 `e2e_<runid>@e2e.test` | 跑完调 `POST /auth/delete-account` 删号 |
| chroma | 默认指向 `scripts/.e2e_real/<RUN_ID>/chroma` | 不污染真实记忆库；`--keep-chroma` 可切到真库 |

运行方式：

```powershell
python scripts/e2e_real_user.py            # 全量
python scripts/e2e_real_user.py --keep      # 跑完保留账号，方便人工复看
python scripts/e2e_real_user.py --keep-chroma  # 沿用真实 data/chroma_db
```

脚本设计上的三个要点：

- **只记录、不中断**：`check()` 永远不抛异常，单条失败不掩盖后面的用例（否则一轮只能得一个结论）；
- **失败必带现场**：失败时把页面上真实存在的按钮文案、HTTP 状态码、响应体摘要一起打出来，下一轮不用猜；
- **残留必须核对**：P12 不只看删号接口返回 200，还要直连 MySQL 查 6 张表的本轮残留并打印。

## 4. 实测暴露的缺陷

### F1（严重·已修）向量记忆从没工作过，而监控是全绿的

**现象**：`.env` 只配了通用 LLM 三件套：

```
LLM_BASE_URL = https://open.bigmodel.cn/api/paas/v4   （智谱）
LLM_MODEL    = glm-4-flash
（没有任何 LLM_EMBEDDING_* 配置）
```

`embedding_settings()`（`后端_核心/agent/llm_client.py:397-399`）的回落链于是拼出
**智谱的端点 + OpenAI 的模型名 `text-embedding-3-small`**，实测：

```
HTTP 状态 = 400
错误码   = 1211
错误信息 = 模型不存在，请检查模型代码。
embed_text() 实际返回 = None
```

而 `/healthz` 当时报的是 `memory.ok=true、指纹一致=true、条数=0` —— **全绿**。

**为什么两道防线都没盖住**：

- 阶段 61 的指纹闸（第 6 道启动自检）只在「库里已经有数据」时才有指纹可比；
  全新部署的库是「未创建」→ 直接放行；
- `/healthz.memory.ok` 的语义被定死为「**库可读**」，不是「embedding 调得通」。

**修复（阶段 63）**：

- `llm_client.检查嵌入配置()`：纯靠配置判断同源性，返回
  `{"同源": True|False|"未知", "端点", "模型", "端点来源", "模型来源", "键来源", "说明"}`。
  「未知」是一等公民（没配 Key = 记忆链路整体不读写，不该被说成配置错）；
  唯一能纯靠配置判出来的错配是「缺省模型名 + 非 OpenAI/Azure 端点」，正好就是本例。
  **刻意零网络请求**——启动自检和 `/healthz` 会被高频轮询，不能把探活变成计费调用。
- `memory.记忆状态()` 多带 `嵌入配置同源` / `嵌入配置说明` 两个键，**不改 `ok` 的语义**
  （改了就和「磁盘坏了」在告警里混成同一条）。
- `api/main.py` 启动自检第 6 道追加 **ERROR 级告警但不拦启动**。
  理由：配置错的后果只是「记忆没启用」，而第 6 道原本拦的是「库里已有数据但语义空间变了」——
  那种情况继续跑会写入错语义向量，而且**改配置也救不回来**，必须拒启动。

覆盖：`tests/backend/test_阶段63_嵌入配置自检.py`（13 条）。

### F2（中·已修）规则快速通道的报表徽标显示成「自动」

`frontend/src/pages/Report.jsx:487` 原本只认两个值：

```jsx
intentSource === 'LLM' ? 'AI 生成' : intentSource === '规则' ? '规则匹配' : '自动'
```

但编排器实际会吐出 **四个**值（`后端_核心/agent/orchestrator.py:274/:280`）：
`LLM`、`规则-受控语句`、`规则-快速路由`、`规则`。后两个都被兜底成「自动」，
和「来源未知」在界面上完全分不出来。

**修复**：`String(intentSource).startsWith('规则') ? '规则匹配'`。
覆盖：`frontend/src/pages/Report.test.jsx` 新增 3 条，红绿灯证据 =
`git stash` 掉修复后 2 条 FAIL、`git stash pop` 后 10 passed。

### F3（信息·已修测试）表格类报表主区域是空的

P6b 连续三轮失败，一度被当成产品缺陷。真实原因是**判据错了**：

```
头部='报表查看  AI 自动生成的智能分析报告 · 数据集共 10 行 5 列  …  规则匹配 表格 …'
```

图表类型徽标是「**表格**」，而 `frontend/src/pages/Report.jsx:538-541` 里
`chartTypeKey === 'table'` 时只渲染一句「表格类数据请在下方『数据表』Tab 中查看」——
**既不渲染 ECharts，也不渲染 `<table>`**。所以 `canvas=False 表格=False` 是正常渲染。

最终判据换成 `frontend/src/pages/Report.jsx:669-674` 那个**无条件渲染**的「导出」按钮当哨兵
（它和标题在同一次 render 里，标题在 + 按钮在 = 这张报表确实加载出来了），
canvas/表格降级为诊断信息，另加一段 `头部文案` 采样——正是这段采样直接定位了 F3。

**遗留 UX 问题（未修，登记在案）**：表格类报表的主区域只有一句提示，
用户必须自己切到「数据表」Tab 才看得到数据。

### F4（信息）`POST /reports/generate` 不是前端走的路

前端走的是 SSE：`frontend/src/api/upload.js:102` → `POST /reports/generate-stream`。
想用 `page.on("response")` 抓响应体是抓不到的（流不结束，`text()` 拿不到完整 body），
run9 因此误报了一次失败。现在脚本改成从 HTTP 侧读回报表：
`GET /reports/`（列表按 `created_at` 倒序）→ `GET /reports/{id}` → `报表.意图来源`。

## 5. 实测顺带确认的几件事

| 结论 | 证据 |
|---|---|
| 真实 LLM 链路是通的，不是「慢到像坏了」 | 探针：「按地区统计销售额」→ **10.94s / 意图来源=LLM / 柱状图**；「帮我看看销售额的构成情况」→ **0.00s / 规则-受控语句** |
| 规则快速通道（阶段 35/39，省 3-4s）确实在生效 | 同上，两句需求一个 10.94s 一个 0.00s |
| 阶段 61 的导出文件名修复在真响应头里成立 | `Content-Disposition="attachment; filename=export.json; filename*=UTF-8''%E6%88%91%E7%9A%84%E6%95%B0%E6%8D%AE-e2e_….json"`，解回 `我的数据-e2e_….json` |
| XSS 标题在前端是安全的 | `dangerouslySetInnerHTML` 全仓库 0 处调用（唯一命中是注释）；`转义HTML` 只用在 echarts tooltip/label；标题走 React 文本插值 |
| 「导出」弹窗偶发首击不开是竞态不是稳定缺陷 | run5/run10 都记录到 `首击即开`，脚本已内置「首击采样 + 再击兜底」 |
| XSS 需求走的是优雅降级，不是漏洞 | `意图来源='规则'`、`LLM失败原因=''`——LLM 产不出可用意图时降级规则，原因未透传（登记为可改进项） |
