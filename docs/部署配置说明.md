# 部署配置说明

本文档面向部署者，说明生产环境必须关注的配置项。全部配置通过项目根目录 `.env` 或系统环境变量注入（系统环境变量优先级更高，`.env` 不会覆盖已存在的环境变量）。

## 快速开始

```powershell
# 1. 复制 .env 模板并填写关键项
# 2. 启动（首次会自动安装依赖）
.\启动.ps1
# 停止
.\启动.ps1 -Stop
```

## 配置项一览

| 配置项 | 默认值 | 生产必改 | 说明 |
|--------|--------|----------|------|
| `AUTH_ENABLED` | `false` | ✅ `true` | 是否启用 JWT 认证。生产必须开启，否则所有接口匿名可访问 |
| `JWT_SECRET_KEY` | `change-me-in-production` | ✅ | JWT 签名密钥，必须用强随机值覆盖（如 `python -c "import secrets; print(secrets.token_hex(32))"`） |
| `JWT_ALGORITHM` | `HS256` | | 签名算法，一般无需修改 |
| `JWT_EXPIRE_MINUTES` | `60` | | token 有效期（分钟），按安全策略收紧 |
| `LLM_API_KEY` | 空 | ✅ | 服务端 LLM API Key。**永远不要下发到前端**，也不接收用户通过请求头传入 |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | | 仅在用户未选择 provider 时作为兜底；正常走 `LLM_PROVIDERS` 白名单 |
| `LLM_MODEL` | `gpt-4o-mini` | | 全局兜底模型；用户选择 provider+model 时以请求级配置为准 |
| `LLM_TIMEOUT` | `60` | | LLM 请求超时（秒） |
| `LLM_TEMPERATURE` | `0` | | LLM 采样温度 |
| `DAA_SQLITE_PATH` | `项目根/data/daa.db` | | SQLite 数据库路径；生产建议指向有备份的持久化目录 |
| `API_HOST` / `API_PORT` | `127.0.0.1` / `8000` | | 后端监听地址与端口 |

## LLM Provider 白名单

白名单定义在 `config/settings.py` 的 `EnvConfig.LLM_PROVIDERS`，结构：

```python
LLM_PROVIDERS = {
    "deepseek": {
        "base_url": "https://api.deepseek.com/v1",
        "default_model": "deepseek-chat",
        "models": ["deepseek-chat", "deepseek-reasoner"],   # 空 = 允许全部
    },
    # ...
}
```

- 前端**只能**传 `X-LLM-Provider` + `X-LLM-Model` 请求头；
- `base_url` 由服务端白名单映射，用户无法指定任意 URL；
- `api_key` 始终取服务端 `EnvConfig.LLM_API_KEY`；
- 添加新 provider = 在 `LLM_PROVIDERS` 增加一条配置，无需改代码逻辑。

## 认证配置

```ini
AUTH_ENABLED=true
JWT_SECRET_KEY=<强随机 32+ 字节 hex>
JWT_EXPIRE_MINUTES=60
```

启动后访问：

```
POST /auth/register  {"username":"x","password":"secret123","role":"analyst"}
POST /auth/login     {"username":"x","password":"secret123"}
# 后续请求头带 Authorization: Bearer <token>
```

## CORS 可信域名

当前 `api/main.py` 中 CORS 为开发默认值：

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],     # ← 生产必须收窄为你的前端域名列表
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

生产建议改为显式列表，例如：

```python
allow_origins=["https://analysis.example.com"]
```

> 注意：`allow_credentials=True` 与 `allow_origins=["*"]` 组合在带 cookie 的场景会失效，生产必须给出明确 origin。

## 前端

- 路由守卫开关：`frontend/src/App.jsx` 顶部 `const AUTH_REQUIRED = true;`
  - 生产保持 `true`；本地免登录演示可改 `false`（需与后端 `AUTH_ENABLED=false` 同步）。
- 构建：`cd frontend; npm run build`，产物在 `frontend/dist`。
- 开发代理：`vite.config.js` 将 `/datasets`、`/reports`、`/health` 代理到 `127.0.0.1:8000`，生产请用反向代理（Nginx 等）替代。

## 数据与备份

- SQLite 数据库文件默认 `data/daa.db`（已 gitignore），包含用户、数据集、报表三张表；
- 上传的原始文件落在 `data/uploads/`（已 gitignore）；
- 生产请将 `data/` 目录纳入备份与监控。

## 已知限制

1. `JWT_SECRET_KEY` 默认值为占位符，**必须**在生产覆盖，否则 token 可被伪造；
2. CORS `allow_origins=["*"]` 仅限开发；
3. 前端 `AUTH_REQUIRED` 常量与后端 `AUTH_ENABLED` 需保持一致，否则出现"前端跳登录、后端不校验"或反之的不一致体验；
4. 前端构建存在 `chunk > 500 kB` 警告（ECharts 全量引入），不影响功能，可按需做动态 import 优化。
