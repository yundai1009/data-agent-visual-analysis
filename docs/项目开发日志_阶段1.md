## 一、本次目标（含可验收标准）

把当前项目的「自然语言 → 报表意图」这一步从纯关键词匹配升级为：

## 二、安全姿态（在写任何代码前先钉死）

| 项 | 规则 |
|---|---|
| LLM 输出形态 | 仅接受固定 schema 的 JSON；不解析 Python 字面量，不用 `eval` |
| LLM 字段引用 | 必须在 `画像["字段列表"]` 内；越界 → 视为失败，回退兜底 |
| LLM 图表类型 | 必须在 `图表类型映射.keys()` 内；越界 → 回退 |
| LLM 代码执行 | **任何情况下都不 exec LLM 输出**。Tool 是后端 Python 函数，参数由 LLM 提供、由后端校验后再调用 |
| 凭据 | 仅从 `EnvConfig.LLM_*` 读取，不在源码中出现 key |
| 超时 | 单次 LLM 调用 ≤ `LLM_TIMEOUT` 秒，超时即回退 |
| 副作用 | LLM 路径与关键词路径都最终走 `生成报表数据`，不写文件、不联网除 LLM API 外 |

## 六、决策记录

### 决策 1：保留 `agent/` 子包，删除 `Agent意图解析.py`

| 维度 | 旧方案 `Agent意图解析.py` | 新方案 `agent/` 子包 | 选新方案的理由 |
|---|---|---|---|
| LLM 调用方式 | 普通 `chat/completions` 无 Function Calling | `chat/completions` + `tools` Function Calling | 面试必考点；Tool Use 是 2024-2026 现代化路线 |
| 集成度 | 已被 `上传报表生成器.py` 调用，`意图来源` 字段透传 | 接通后保留同样的字段透传 | 接通代价小（4 处改动） |
| 字段非法时 | 软降级（默默改成自动推荐/补一个数值字段） | 硬拒绝（返回 None，上层走关键词兜底） | 失败可见，便于跑评测集统计 LLM 真实成功率 |
| 多轮 ReAct 扩展 | 单轮实现，要扩多轮需重写 | `TOOL_SCHEMAS` + 编排器结构天然多轮友好 | 阶段 2 平滑演进 |
| 错误观测 | 仅 logger.warning | 每个失败节点都 logger.warning | 二者打平 |

### 决策 2：LLM 不生成代码

拒绝粘贴方案中的 `exec(LLM 生成的 pandas 代码)` 路线，原因写在 `docs/LLM接入说明.md` 第三节"为什么不让 LLM 生成可执行代码"。

## 七、面试可讲点（求职资产）

1. **安全姿态**：解释为什么选 Function Calling + 受控 Tool 而不是 `exec(LLM 代码)`，能讲清 AST 白名单 / 子进程隔离的工程代价与替代方案
2. **降级链路**：6 条失败路径全部静默回退到关键词匹配，主链路永不报错
3. **可观测性**：每条 LLM 失败路径 `logger.warning` + 响应字段 `意图来源` 让运营能看到 LLM 命中率，便于跑评测集合
4. **字段白名单校验**：白名单不只在 prompt 里要求，后端再校验一次，杜绝 LLM 编造字段名
5. **协议兼容**：`OpenAI ↔ DeepSeek` 同协议，切供应商只改 `.env` 三行
6. **测试工程**：26 个不依赖网络的单元测试覆盖解析层/校验层/降级路径全部出口
